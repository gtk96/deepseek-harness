## 发现（按 P1/P2/P3）

### P1 阻断

无。r4 的 5 个 P1 均在 `aedc6a7` 隔离提交中复核通过。

### P2 需修

1. **r4 P2-2 的闭合治理值仍未完成。** 对抗脚本在没有绕过 `authorize_semantic_query` 的情况下得到：`AUTHORIZED_AGGREGATION=arbitrary_sqlish_value`、`AUTHORIZED_DIMENSION_TYPE=bogus_type`、`AUTHORIZED_ALLOWED_OPS=nonsense`。这意味着一个标记为 published 且获显式授权的治理记录可以把非法聚合、维度类型和操作符带入不可变授权结果，只在后续恰好使用相关值时才可能失败。应为发布状态、数据源、聚合、维度类型/操作符、策略主体/资源/effect 定义闭合领域值，或在持久化到领域映射时统一严格解析，并让授权快照只包含已验证值。
2. **r4 P2-3 的错误分类依据仍未落地。** HTTP 字符串码已经修复，但 `e9ccfe3..aedc6a7` 对分类表只增加 `ORDER_BY_INVALID`，没有说明 policy 与 semantic 的归类原则。应明确资源存在性/发布状态、MVP 数据源限制、授权缺失和治理配置错误各自映射哪一类稳定外部码，并用表驱动测试固定，避免客户端行为随内部原因码调整漂移。

### P3 建议

1. `aedc6a7` 中 `authorize_request` 的 Git 引用只出现在定义和单元测试，没有实际内部路由调用；这是后续 Query Broker 集成范围，本轮仅证明 Task 2 应用函数和统一 handler 可组合，不宣称真实问数端点已端到端验证。
2. 隔离测试有 1 个 Starlette/httpx 弃用告警，不影响 Task 2 结论。
