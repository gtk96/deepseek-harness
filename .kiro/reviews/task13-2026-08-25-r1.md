## 发现（按 P1/P2/P3）

### P1 阻断

1. **问数生命周期没有真实闭环，完整生命周期审计和终态浏览器安全扫描均无法成立。** `OwnedTurnDispatcher` 成功后只写 `dispatch_status=accepted`；动态证据仍是 `status=queued`、空 answer/result。DSH ingress 没有安全回写 running/terminal/answer/result 的协议，`service.update_turn_state()` 仅存在而无生产调用。影响 Requirements 2.5、7.1 和 Task13.1/13.2，并使真实用户永远轮询不到终态。
2. **DSH assembled transcript/session 缺少 Task13 指定的自动敏感扫描。** 当前 snapshot 是固定 stdout 相等比较，composition 只排除三个业务 ID；没有对实际完整 Session events/artifact 扫描 AK、SK、JWT、Authorization、Cookie、raw SQL，也没有负例夹具证明扫描器会失败。当前快照人工扫描 0 命中只是一次性观察，不满足 Requirements 1.7、3.7、10.5 的持续门禁。

### P2 需修

1. **Requirement 7.7 的应用日志关联能力缺失。** Query Broker 的审计有 turnId/jobId，但成功与各失败路径没有携带 turnId、稳定错误码和安全 jobId 的结构化应用日志，无法按 turnId/时间把应用日志、审计和 MaxCompute 作业三者关联。
2. **授权拒绝审计和跨面扫描尚不完整。** `query.authorized/denied` 未记录适用的请求指标/维度编码；真实组合扫描只覆盖 queued 浏览器响应、无效 assertion 日志和早期审计，没有覆盖成功、拒绝、失败、超时终态的浏览器投影与完整日志/审计集合。影响 Requirement 7.2 和 Task13.2，但可在闭合生命周期后补齐。

### P3 建议

无。
