# Agent Note: 预设条件——首轮承诺与稳定 persona 带

Status: implemented

[English](2026-08-24-preset-conditioning-principles.md) | 中文

## 问题

会话的行为模式由第一条请求决定。首条请求之后轨迹被强锚定：之后再改 persona 或可见工具目录，最多扰动一个推理块，随后原始轨迹重新确立。打算"中途扭转"行为的预设作者——加宽目录、换 persona、在首轮之后追加指令——是在依赖一个并不存在的机制。另外，模型行为沿 persona 轴不是连续可调的：它坍缩成 plan-first 带和 doer 带，中间是行为退化的不稳定混合带。这两条事实此前在仓库 AGENTS.md 中都没有陈述，预设与 profile 作者缺少"条件何时生效、persona 怎么摆放"的书面指引。

上述观察来自社区 `dsh-routing-suite` 研究产物（经第三方 harness 在 DeepSeek V4 Pro 上实测）；该套件随附的机制是另一回事，此处不予采纳。

## 决策

两条规则记录于本 note；AGENTS.md 已达词数预算，只在其中放一行指向本 note 的指针：

1. **首轮摆对条件，不中途扭转。** 在第一条请求前摆好 persona 与核心工具集；不要指望会话开始后再改 conditioning 来改变行为。
2. **朝一个稳定带写，绝不写混合。** 预设选择一个 plan-first 或 doer 带；不要混搭条件并期待得到其中任一侧的更强行为。

规则作为经验性指引，而非发布门禁。`dsh-routing-suite` 的运行时注入器与关键词计数分类路由不予采纳（见替代方案）。原则的表述不带套件的机制，来源标注为社区产物而非 DeepSeek 结论。

## 替代方案

- **把套件的运行时注入器收为依赖。** 否决：它绕开了"持久化插件只有一种状态——配置、由 HMR 事务性对账"的官方装配模型。向运行中的 web 注入违背 AGENTS.md 的"插件而非 loop 改动"立场，并把第三方运行时 hack 引入生产 fork。
- **把关键词计数分类路由作为预设机制。** 否决：按关键词计数分类很脆弱，且只在一个模型和 harness 上实测过；没有泛化证据，依赖它会让预设行为耦合到仓库无法控制的提示词词表。
- **AGENTS.md 保持沉默。** 否决：预设与 profile 组合是当前进行中的工作（受控问数 profile），两条规则会实质改变这些预设的写法。

## 后果

预设与 profile 作者现在有书面指引：在首条请求前组装稳定 persona 与核心工具集，绝不混搭条件。套件工具不进仓库。因为来源是社区实验，规则作为经验记录表述，仍受仓库自有证据检验；观察到相反行为时应更新本 note，而不是把它当权威。
