# 按需阅读：边界与实现自检清单

> SKILL §2.2 和 §4 的展开。命中相关变更时再读，不必每次全量过一遍。

## 定边界时

- 能复用已有扩展点和靠谱依赖就复用，别硬抽象。
- 默认值放在显式解析/归一化那一步，别藏在执行函数里的 `?? default`。
- 会随环境变的东西做成可校验配置项，别写死成常量。
- 能独立判断的非法配置在加载时就报错，其他错误在最早能定位的地方报，别静默跳过。
- 在解析、文件、持久化、外部 JSON、进程/Worker、网络这些边界上校验不可信数据；同进程内已定类型的数据不用重复设防。
- 保留判别字段和可扩展联合类型的完整分支（封闭联合用 `assertNever`，开放联合走有文档的默认分支），别静默丢弃未知情况。
- 管好所有权和生命周期：注册/释放、取消、清理、错误传播要成对。
- 写死的枚举别升为全局标准——比如某适配器的能力列表由它自己声明，核心只透传。
- 协议归提供方管：像终端提示符这类协议由提供方自愈，消费方别去硬改。

如果方案要重写主循环、引入两套事实源、加宽泛兼容层，却还没证明现有边界兜不住，先停下找更简单的扩展。

## 动手实现时

- 测试写外部能观察到的行为和重要非法/边界情况，别复述实现细节。
- 异步状态不是同步状态：别把 `running`/`idle` 当成单条消息的结果；后台任务可能跨 turn，取消可能丢弃未开始的项。
- 清理要等到静止：发了 kill/abort 还要等子进程真正退出，先关监听再杀进程。
- 回调异常由调度器兜住：用户回调抛错不能把整条链带崩。
- 正交结果分开报告：比如既超时又退出 0，要把 `timedOut`/`exitCode`/`signal` 各自报清楚。
- 别把不可信输出丢进 ambient 环境或可预测路径；临时文件用私有目录、随机名、排他创建。
- 涉及 `settings` 这类部分视图编辑，走"算 diff 发 ops + 带版本号防覆盖"，别用全量 `replace` 把看不见的字段洗掉。
- 公开或模型可见行为变了，同步更新对应契约、快照或 SDK 投影。
- 别用 normalizer 盖住失败用例，别为接受非法输入放宽类型/校验，别用 mock 代替真实集成点。
- 同一子任务内别反复刷同一句进度，阶段变了或有新证据再更新。
